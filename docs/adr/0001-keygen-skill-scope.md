# ADR-0001: keygen 通用技能的范围界定

- 日期：2026-08-08
- 状态：已接受

## 背景

Binary Ninja v5.3.9434 逆向分析产出了完整的密钥替换型注册机（keygen），
包括方法论、探测工具与 BN 特有实现三层资产。计划将其固化为通用技能，
用于寻找其他软件的许可证生成破解方案。

## 决策

1. **分层结构**：通用技能 = 方法论（找验证逻辑 → 分类谱系 → 选攻击原语）
   + 跨软件通用探测工具（脚本）+ Binary Ninja 作为案例附录。BN 特有实现
   （C7 指令模式、XOR 密钥、JSON 字段序）只作为案例，不写入主流程。
2. **覆盖范围**：只覆盖注册机可行的三个谱系（非对称签名+内嵌公钥、
   对称认证+内嵌密钥、纯算法序列号）。在线激活与壳保护作为"注册机不可行"
   的退出路径指向补丁/劫持，不纳入技能主体。
3. **交付形态**：生成型。技能输出可运行的注册机实现，而非仅分析报告。
   第一版仅完整实现"密钥替换"原语（BN 已验证）；"密钥提取"与
   "凭证伪造"作为决策树分支与 TODO 模板。
4. **术语**：keygen 严格限定为"凭证伪造 + 密钥替换 + 密钥提取"三个攻击
   原语的实现；patch / hijack 明确排除在注册机之外（另见 CONTEXT.md）。

## 备选方案

- **全谱系一次交付**：同时实现对称密钥提取、序列号算法重实现、ECDSA 替换。
  拒绝理由：工作量约为当前方案的 3 倍，且无第二真实目标验证，交付即失约。
- **纯分析型**：只输出"验证机制是什么、keygen 是否可行"。
  拒绝理由：用户明确要求生成型，分析型不满足"生成许可证"的目标。

## 后果

- 技能在第一个非 BN 目标上验证前，不宣称"任意软件可用"，只宣称
  "方法论 + 密钥替换模板已用 BN 验证"。
- 密钥提取 / 凭证伪造分支需要未来在真实目标上补全后提升为已验证原语。
